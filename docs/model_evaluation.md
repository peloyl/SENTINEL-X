
# Model Evaluation
See `models/evaluation_report.json` generated by actual training runs - never hand-written.
Primary metric: PR-AUC / Average Precision (fraud is rare; ROC-AUC alone is misleading).
Also: precision, recall, F1, confusion matrix at a threshold chosen on the VALIDATION split by max F1.
Split: time-aware (sorted by Time; last 20% test, preceding 20% validation). Preprocessing fit on train only.
SMOTE is an optional experiment (`train_all(..., use_smote=True)`), applied only inside training; default uses scale_pos_weight.

## Actual run on this machine (2026-11-21, SYNTHETIC demo data - NOT real-world performance)
Dataset: 20,000 synthetic rows, 80 fraud (0.40%). Splits: train 12,000 / valid 4,000 / test 4,000. scale_pos_weight=243.9, chosen threshold=0.05 (validation F1).
- XGBoost (test): PR-AUC 0.9936, ROC-AUC 1.0000, Precision 0.923, Recall 1.000, F1 0.960, CM [[3987,1],[0,12]]
- Logistic Regression (test): PR-AUC 1.0000, ROC-AUC 1.0000, Precision 0.750, Recall 1.000, F1 0.857, CM [[3984,4],[0,12]]
These near-perfect numbers are expected: the synthetic fraud rows were generated with strong shifts in V10/V12/V14/V17, so the demo problem is far more separable than real fraud. Do NOT quote them as real fraud-detection performance. Re-run with the real Kaggle CSV for meaningful metrics.
